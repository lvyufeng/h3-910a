# R194 — "减少 tile 数"被 UB 容量锁死在 1.089×

## 一、动机

R193 拟合出 `T = 83.53 ms + 2.922 µs × tiles`，指出两个可相乘的杠杆：
1. 减少 tile 数
2. 降低每 tile 系数

本轮测第 1 条能走多远：把 `Bc` 从 384 继续往上推（512 / 768 / 1024 / 1536）。

## 二、结果

| Bc | 结果 |
|---|---|
| **384** | **141.98 ms（1.089×）** ✅ |
| 512 | ❌ UB 溢出 |
| 768 | ❌ UB 溢出 |
| 1024 | ❌ UB 溢出 |
| 1536 | ❌ UB 溢出 |

失败点很明确，在 TIK kernel 内部：

```
flash_attention_fwd.py:445
  Sij_ub_zN = tik_instance.Tensor(FP16, (self.Bc // 16, q_blk_h_aligned, 16), scope=UB)
```

分数 tile 的 UB 缓冲区按 `Bc × Br_aligned × 2 字节` 增长：
- `Bc=384, Br=128` → **98 KB**
- UB 每核只有 **192 KB**，其余（Q/K/V 分块、softmax 中间量、输出累积）还要占一大半
- `Bc=512` → 131 KB，装不下

⇒ **`Bc=384` 就是实际可达的上限。**

## 三、两个重要的验证

1. **`Bc=384` 复现性极好**：本轮 141.98 ms，R191 是 142.00 ms，差 0.02 ms。
   **R193 的拟合预测 140.99 ms，误差 0.7%。** 拟合是可信的。
2. R193 的线性模型在 Bc=384 上也成立 ⇒ 该模型可用于外推判断，但**可行域被 UB 限死**。

## 四、决定性的结论

| 杠杆 | 可达上限 | 是否够 1.50× |
|---|---|---|
| 减少 tile 数（Bc 到 384） | **1.089×（省 0.6 s）** | ❌ **远不够** |
| 降低每 tile 系数（2.922 µs） | 理论可到 ~1.9× | ✅ **唯一的出路** |

**"调参数"这条路到此为止了。** 剩下 1.37× 必须来自
**降低每 tile 的固定成本**——即流水线重叠、双缓冲、cube/vector 相位交错。

而这已经**不是配置问题，是内核实现问题**：
需要改 MindIE 的 TIK 内核（`/tmp/fa_pkg/flash_attention/...`），不是改 `fa910a.py` 的参数。

## 五、对 10 s 路径的最终 FA 判断

| 事项 | 结论 |
|---|---|
| 核预算 | ❌ 已是硬件上限（R188） |
| tile 调优 | ❌ 上限 1.089×（R191/R194） |
| softmax/减少 op | ❌ 向量只用 ≤21%（R190） |
| **流水线重叠** | ✅ **唯一可行方向**，需改 TIK 内核实现 |
| 理论收益 | 完全消除开销 → 1.89×，够 1.5×（R193） |

**FA 的 1.5× 在物理与算术上都可达，但要动内核实现，不是改参数。**

## 六、诚实边界

- 只测了 `N=41792`（补齐 43776）单一形状；其他 N 的 UB 上限可能不同
- UB 溢出的具体剩余空间未精确计算（未逐项统计 kernel 内其他 buffer 用量）
- 改 tile ⇒ 累加顺序变 ⇒ **数值非等价**，本轮所有数据仅为测量
- 未尝试"缩小 Br 换更大 Bc"的组合（如 `Br=64, Bc=768`）——理论上分数 tile 大小
  是 `Bc×Br`，同乘积下不同形状可能都装得下；这会改变 q-block 结构，是另一个实验。
  **这是唯一还没穷尽的参数方向**，若要做值得单独一轮。
