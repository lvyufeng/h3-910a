# R148 — FP32 范围保护快路径的身份验证：**INCONCLUSIVE**（但拿到一个可靠事实）

目标：证明 `peak ≤ 32752 ⇒ scale=1 ⇒ prologue 是恒等变换`，从而用一个条件快路径拿到 R147 估的上界收益。
方法是**模型数学完全不动**：每个 guard 调用先照原样算原生结果（并返回它），另算一份快路径结果，
再加一次"原生再算一遍"的对照，step 结束后比较位。

## 可靠的结果：peak 分布（100 次 guard 调用，8 rank 一致）

| 项 | 值 |
|---|---|
| 调用数 | **100**（2 层 × 50 块） |
| peak 最小 / 中位 / 最大 | 20.453125 / 434.6 / **193531.6** |
| 落在 `scale==1` 区间 | **97** |
| 超过 32752（需要缩放） | **3** |

**结论：快路径只能是"条件启用"，不能无条件跳过 prologue** —— 有 3 次调用确实越过 32752（最大 193,531），
缩放分支必须保留。这一条是确定的。

## 身份验证本身：**INCONCLUSIVE，不能下结论**

对照（原生跑两遍）**自己就不逐位相同**：

- `native_vs_native_control`：`all_bit_identical=False`，max differing **10983168**，
  relRMS 1.2600，maxabs 17944.5

原因：layerwise offloader 在整个 step 里持续 `set_tensor_storage` 重绑存储，我"保留"的输出张量
在 step 结束前被回收复用，所以 step 后再比较时数据已被覆盖。**这个 harness 无效，`native vs fast` 的对比因此什么也证明不了。**

我把它标成 INCONCLUSIVE，而不是"快路径不逐位相同"——后者不成立，因为我连参照系都没建立起来。

## 一个有意义的推论

对照失败本身说明：**guard 里的 `mm` 输出在相同输入下并不逐位可重复**，与 R137"原生组件不可逐位重复"一致。
因此"逐位相同"这个门槛**原理上无法通过输出比较来证明**；若要走这条优化，只能改用
**噪声带判据**（R138/R139 那套），并需要用户对这种判据给出决定。

## 另一个意外（需先查清再谈收益）

记录的输入形状是 **[2043, 3584] / [2043, 7168]**，不是 R147 在 block 内测到的 **10448**。
说明这些 guard 调用来自**另一个阶段**（可能是 token_refiner / 末尾层），
所以在用 R147 的 1.665 s 上界之前，需要先把"100 次调用分别属于哪些阶段"对清楚。

2. 用噪声带形式给出"快路径 vs 原生"的分布，而不是逐位判定；

## 限制

- 本轮未改模型数学（模型始终返回原生结果）、未改默认路径、未安装候选。
- 3 次超 32752 的调用说明收益是条件性的；具体能省多少依赖第 1–3 步。
- 前几次失败均 fail-closed（in-forward D2H 冲突、`.amax()` 归约写法与原生不一致、label 未更新），回执保留。
