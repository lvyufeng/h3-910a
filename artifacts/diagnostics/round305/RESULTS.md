# R305 — 逐行误差画像：不是分块覆盖，而是「C 可能按转置存」

## 一、逐 16 行误差画像

```
probe got[0][0..3] = 3.5547 -3.2852 -5.0898 -0.8999
probe ref[0][0..3] = 3.5545 -3.2861 -5.0882 -0.8997
PERBLOCK rows  0..15 maxdiff=21.5545 bad=7621/8192  (93%)
PERBLOCK rows 16..31 maxdiff=27.4668 bad=8140/8192  (99%)
PERBLOCK rows 32..47 maxdiff=22.2427 bad=8134/8192  (99%)
PERBLOCK rows 48..63 maxdiff=20.5030 bad=8143/8192  (99%)
```

- **四个块全部错** ⇒ 排除「分块覆盖不全」（若只算了一块，应只有一块错）；
- 但 `got[0][0..3]` 与 `ref[0][0..3]` 吻合到 1e-4 ⇒ 基址、A/B 绑定、D=128 的归约都没错。

## 二、新的主假设：C 以转置存储

若 Matmul 实际按 **转置** 写出（即 `got[i][j] ≈ ref[j][i]`），则：

- `got[0][0] = 3.5547` 与 `ref[0][0] = 3.5545` 吻合——因为 `ref[0][0]` 在转置后位置不变；
- `got[0][1] = -3.2852` 应等于 `ref[1][0]`（而非 `ref[0][1]`）；
- 逐块统计全部错（93–99%），与「整体转置」完全一致。

这与我们 `MatmulType` 里 **A/B 的角色/转置语义**有关：`isTransposeB=true` 的 B 语义 + C 的 ND 布局
组合起来，可能导致实际计算的是 `k · q^T`（512×64）而不是 `q · k^T`（64×512），
写进同样大小的 GM 缓冲后表现为「转置」。

## 三、验证方法（R306，一次就能定）

在 harness 里同时计算两种参考并各报一个 relRMS：

1. 正常：`ref[i][j] = q[i]·k[j]`（当前）；
2. 转置解释：`refT[i][j] = q[j]·k[i]`（即 `got` 视作 512×64 再转置）。

若转置解释的 `relRMS` 降到 1e-3 量级 ⇒ 只需在 kernel 里把 A/B 对调
（`SetTensorA(kGm)`、`SetTensorB(qGm, true)`）并相应调整输出形状，或改用 `SetTensorA(qGm, true)`。
