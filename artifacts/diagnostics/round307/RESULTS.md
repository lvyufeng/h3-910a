# R307 — NZ 布局假设也被否；下一步用「列命中图」直接反推置换

## 一、本轮实验

把原始输出缓冲按 **NZ 16×16 分形规则**重排回行主序后再比对：

```
NZ_CHECK  relRMS=1.404e+00 maxdiff=22.31 bad=32493
（ND 直读 relRMS=1.395e+00）
```

⇒ **NZ 假设同样被否决**。两种布局解释都解释不了观测。

## 二、已被排除的解释（累计）

| 假设 | 结果 |
|---|---|
| 分块覆盖不足 | ❌ 四个 16 行块全错 |
| 简单转置（`got[i][j]≈ref[j][i]`） | ❌ relRMS 1.425 |
| NZ 16×16 分形 | ❌ relRMS 1.404 |
| UB 超限导致崩溃 | ❌ 32 MB workspace 后不再崩溃 |
| workspace 偏移语义 | ❌ 已按 32 MB 收紧后仍可运行 |

## 三、剩下的最关键事实

- `got[0][j]` 对 **j=0..3 与参考吻合到 1e-4**；
- 每行只有约 **35/512 ≈ 7%** 元素正确；
- 说明：**A=q 的绑定、K=128 归约、首元素基址都正确**，错误集中在 **B(k) 的读取或 C 的写入排列**。

## 四、下一步（一次定案的实验，R308）

**列命中图**：对第 0 行，逐 j 判断 `|got[0][j] - ref[0][j]| < 1e-3`，把正确的 j 列表打印出来。

- 若命中集合是 `{0,1,2,3, 16..19, 32..35, ...}`（每 16 列前 4 个）→ C 写入按 **每 16 列一组、组内只写前 4**（fixpipe 的 N 粒度问题）；
- 若是 `{0, 128, 256, 384}` 之类 → 分形/块粒度问题；
- 若命中集合无规律 → B(k) 的 ND 读取 stride 错（多半是 `isTransposeB` 与 B 的 actual shape 不匹配）。

判据明确后，改 kernel 一处参数即可收敛。
