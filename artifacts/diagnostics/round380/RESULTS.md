# R380 — FA 内核（V1 128/384）已达该 TIK 实现的结构极限

## 一、当前状态

| 项 | 值 |
|---|---|
| 内核 | FA V1（PV 前置）+ Br=128 / Bc=384 |
| 单体耗时 | **126.5 ms**（msprof 内核时间）/ 128.8 ms（事件计时） |
| pipe 占用 | vec 49.1% / mac 27.1% / scalar 21.6% / mte1 20.1% / mte2 11.5% / mte3 10.5% / memory_bound 23.4% |
| 模型占比 | 5.8 s / 15.55 s（38%，最大单项） |

## 二、本轮消融（均在 V1 128/384 上重建内核）

| 消融 | 耗时 | 结论 |
|---|---|---|
| 基线 | 128.85 ms | — |
| **noexp**（删掉 softmax 的 h_exp） | 128.85 ms | **exp 不在关键路径** |
| **nosub**（删掉逐 plane 的 h_sub 循环） | 128.89 ms | **sub 不在关键路径** |

即：减少向量数据量/指令都不改变总时长 ⇒ 内核**不是向量吞吐受限**，而是
**逐 tile 的依赖/同步延迟受限**（272,916 tiles / 126.5 ms ≈ 0.46 µs/tile）。

这也解释了此前 R371/R372 的结论：双缓冲/重排/多线程之所以无效，是因为瓶颈在同步时延本身。

## 三、更大 tile 同样被封死

| 组合 | 结果 |
|---|---|
| Br=256 / Bc=224, 192, 160 | `Oi_ub_zN` 需 131072B > UB 可用（10880~35456B） |
| Br=192 / Bc=256 | `Oi_ub_zN` 需 98304B > 48640B |
| Br=128 / Bc=384,448,480 | 均 128.8 ms（不敏感） |

⇒ 在 `S + Oi_ub` 的 UB 预算下 Br=128 已是上限，tile 空间关闭。

## 四、结论

- 当前 TIK FA 内核在 910A 上的实际极限约 **126.5 ms/call**；
- 进一步提速只有一条路：**从零重写内核**（显式双缓冲 + 手写 pipe 依赖 + 更省的 UB 布局），
  这是多轮迭代量级的工作，且此前 AscendC 路线在 ND2NZ 上受挫；
- 本轮不采用任何新的 FA 改动；交付组合保持 **15.5489 s/step**。

- 内核 pipe 数据：`/tmp/prof_fa_v1`（msprof PipeUtilization）。
