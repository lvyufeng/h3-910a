# R164 — 对抗测试：快速检查**不是等价的**（R163 的结论必须收窄）

## 为什么要做

R163 在 **465 个真实被审张量**上比对，计数全部一致。但那些张量的坏值计数**全是 0**，
所以那只证明"双方都报 0"，**没有证明在有坏值时双方一致**。本轮用构造输入直接打边界。

## 结果（NPU，16 个用例）

| 用例 | 原生 | 快速 | 判定一致 |
|---|---|---|---|
| 全有限值 | [0,0] | [0,0] | ✅ |
| 单个 NaN / +Inf / -Inf | [1,0] | [1,0] | ✅ |
| 单个 ±65504 | [0,1] | [0,1] | ✅ |
| 两个 65504（重复） | [0,**2**] | [0,**1**] | ✅ 判定一致，**计数不同** |
| **NaN + 65504** | **[1,1]** | **[0,0]** | ❌ **漏检** |
| **NaN,±Inf,±65504 混合** | **[3,2]** | **[2,0]** | ❌ **漏检** |
| 边界邻域 / 次正规 / 零 | 一致 | 一致 | ✅ |

**verdict_mismatches = 2；count_mismatches = 4。**

## 两个缺陷

1. **NaN 污染极值**：张量含 NaN 时 `max()`/`min()` 返回 NaN，`NaN == 65504` 为假 → **饱和检测整个丢失**。
2. **小张量上 `isnan().sum()` 返回 0**：2 元素 NaN 用例里非有限计数也丢了。这条需单独查清 `isnan` 在该形状上的行为。

## 更正 R163

R163 我把"465 次计数一致"写成了**已证明的等价**。**这个说法过强，现收窄为：**
> 在 465 个"坏值计数为 0"的真实张量上，两个实现都报 0。

**快速实现按现在的写法不能采纳。**

## 可修复的方向（待验证）

快速路径**只在张量不含非有限值时才合法**。安全版本应当：
1. 先测 finiteness；
2. 通过 → 用 `max/min` 的存在性判定饱和（此时无 NaN 污染，等价成立）；
3. **不通过 → 回退到精确计数路径**。

这样在常规情形（真实激活都是有限值）仍能拿到收益，同时**永不丢失检测**。

## 对那 2.87 s 的影响

- 审计确实花掉约 **2.87 s** 步时（R162）；
- 快速检查确实每次便宜 **2.6×**（R163）；
- 但它**在通过对抗套件 + 真实数据比对之前不能使用**。
