# R169 — 只读可行性：延后检查的内存账 **边际、很可能不行，但未被证明不可能**

## 动机

R168 证明审计的代价是**每层的串行化点**，不是算术。下一步自然是"不在每层扫描，改到 forward 之后做"。
但这要求每个被审张量活到检查时刻。本轮只读地算这笔账（**未上机**）。

## 账目

| 项 | 数量 | 合计 | 来源 |
|---|---|---|---|
| `mlp.fc1` 输出 **[10448, 14336]** FP16（285.7 MiB） | 50 | **13.95 GiB** | **实测**（R163/R167 回执记录形状） |
| `qkv_proj` 输出（假设 [10448, 5376]） | 50 | 5.23 GiB | **假设，未实测** |

| **净余量** | | **0.96 GiB** | |

## 判定：边际

**我这份笔记的第一稿写的是"不可行"——那是错的，算术不支持。**
19.4 GiB vs 20.36 GiB 是"很紧"，不是"放不下"。**结论已在写进 Issue 前改正。**

### 为什么实践上很可能不行

- 净余量只有约 **1.0 GiB**；
- offloader **每层都在流式搬运权重**，需要暂存空间，这个预算没有为它留；
- 11.64 GiB 是 **mlp 调用期间**的 reserved，整步峰值可能更高；
- 这台设备在 31.06 GiB 上连整模型常驻都 OOM（R157），碎片化余量本就很小。

### 什么能一次性定论（都很便宜）

1. 实测 `qkv_proj` 与 `adaln_proj.linear` 的**真实输出形状**；
2. 实测**整步**的 peak reserved bytes（而不是 mlp 调用期）。

现有 harness 钩子上加一行就能拿到——**我还没做**。

## 成立与不成立的分界

- **成立**：R166/R167 的等价性证明、R168 的测量与结论。
- **不成立**："检查可以延后"——它取决于上面这个内存预算能否成立，而**两个方向都未被证明**。

## 唯一还值得试的变体

**侧流扫描**：张量仍存活时在另一条流上扫，内存有界，每张量一条生产者→消费者事件，
并要求分配器在扫描完成前不复用缓冲。**扫描能否跟上生产速度是待测问题**。

## 对你决策的影响

R168 之后我建议的"批量延后"**不要基于那个洞见就直接授权**：按现有数字它太紧，
应当**先测再建**，而我没测。
