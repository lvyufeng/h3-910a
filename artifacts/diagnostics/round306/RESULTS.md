# R306 — 转置假设被否；下一步用「列索引命中图」定位

## 一、实验

在 harness 里对 `got[i][j]` 与转置参考 `ref[j][i] = q[j]·k[i]` 比较：

```
TRANSPOSE_CHECK relRMS=1.425e+00 bad=4068
（正常参考 relRMS=1.395e+00）
```

⇒ **转置假设被否决**：两种解释的误差同量级，说明看到的不是简单的行列互换。

## 二、当前已知精确事实

| 事实 | 证据 |
|---|---|
| 基址、A/B 绑定、K=128 归约正确 | `got[0][0..3]` 与 `ref[0][0..3]` 吻合到 **1e-4** |
| 四个 16 行块全是 93–99% 元素超差 | PERBLOCK 画像 |

**关键算术**：每块 8192 元素中约 571 正确（≈7%），即平均每行约 35/512 个元素正确。
这个比例很像 **fractal（16×16 NZ）布局**下的命中率（每行只在特定分形列上有正确值）。

## 三、下一假设与验证（R307）

**假设**：`Matmul` 的 C 输出实际按 **NZ（16×16 分形）** 写进 GM，而我们的 harness 按 ND 行主序读，
于是只有处于「分形 ↔ 行主序重合位置」的元素正确。

**验证（一次即可判定）**：
1. 在 harness 里把 `ho` 按 NZ 规则重排成行主序（对每个 16×16 分形块做 `[c0][c1]` 索引映射），
   再与 `ref` 比较 relRMS；
2. 若 relRMS 掉到 1e-3 ⇒ 确认 NZ 输出，kernel 侧改用 `CubeFormat::NZ` 或在写回前做 NZ→ND 转换；
3. 若仍不行，改为逐列命中图：统计每行中「正确元素」的列索引集合，直接看出布局规律。
