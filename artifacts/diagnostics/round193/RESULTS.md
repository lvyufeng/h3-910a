# R193 — **实测确认**：FA 有 47% 是每 tile 固定开销（不需要 profiler）

## 一、怎么绕开 profiler 拿到的直接证据

R192 发现这台芯片不支持设备侧 profiling（`Device profiling is not supported on current chip`），
所以占用率时间线拿不到。但 R191 的五个配置本身就是一个**受控实验**：

**关键事实：五个配置的总 flops 几乎完全相同（3.444–3.467 TFLOP，差 <1%），
而耗时从 142.00 到 254.98 ms 差 1.8 倍。**

同样的计算量，只有"切法"不同 ⇒ 差异只能来自**切法本身的开销**。

## 二、拟合结果

对 `br=128` 的四个点（同一 q-block 结构，tile 数从 19665 到 58653）：

```
time_ms = 83.53 + 2.922 µs × tiles
```

| tiles | 实测 | 拟合 | 残差 |
|---|---|---|---|
| 19,665 | 142.00 | 140.98 | −1.02 |
| 24,858 | 154.57 | 156.16 | +1.59 |
| 29,412 | 169.94 | 169.46 | −0.48 |
| 58,653 | 254.98 | 254.89 | −0.09 |

**最大残差 1.59 ms = 最快点的 1.1%。在 3 倍 tile 数范围上，这个线性关系近乎完美。**

（`br=64/bc=304` 那个点落在同一条线外——br 改变会改 q-block 结构，属另一个变量，已排除。）

## 三、这直接把 FA 的成本拆开了

在基准配置（`br=128, bc=304`, 24858 tiles, 154.57 ms）：

| 成分 | 值 | 占比 |
|---|---|---|
| **每 tile 固定开销** | **72.6 ms** | **47.0%** |
| 与 tile 数无关的部分（含 cube 计算） | 81.9 ms | 53.0% |

也就是说：**FA 有近一半的时间不是在做计算，而是在付"每 tile 的固定成本"**
（依赖链同步、缓冲切换、波次调度、tile 之间的串行等待）。

## 四、这确认了 R190 的气泡推断

R190 是**算术推断**（cube 24% / vector ≤21% / HBM 23%，三者同时低 ⇒ 没重叠），
本轮是**实测拟合**（同 flops 下耗时纯由 tile 数决定）。

两者独立指向同一结论，**气泡/固定开销假设现在有直接证据了**，不再是推断。

## 五、对 10 s 的意义（这是本轮最重要的数字）

| 情景 | FA 每步 | 加速 | 是否够 10 s |
|---|---|---|---|
| 现状 | 7.454 s | 1.00× | — |
| 固定开销**减半** | **5.70 s** | 1.20× | ❌（需 1.50×） |
| **固定开销完全消除** | **3.95 s** | **1.89×** | ✅ **超过所需的 1.50×** |

**结论：只要把每 tile 固定开销压掉够多，FA 的 1.5× 目标就能达到——
完全消除能到 1.89×，绰绰有余。**

这就把 FA 从一个"不知道能不能做到"的目标，变成了**"压 tile 开销"这一个明确的工程量问题**。

## 六、具体的优化方向（由拟合直接给出）

拟合式 `T = 83.5 + 2.922 µs × tiles` 说明两条路，且**可以叠加**：

1. **减少 tile 数**（降 `tiles` 项）
   - `Bc=384` 已实测把 tiles 从 24858 降到 19665 → 142.00 ms（1.089×）
   - 若能上到 `Bc=768`，tiles 再减半 → 预计 ~83.5 + 2.922×9833/1000 = 112 ms（1.38×）
   - **受 UB 容量限制**，需确认 Bc 上限
2. **降低每 tile 的固定成本**（降 2.922 µs 这个系数）
   - 这是流水线重叠/双缓冲要解决的问题（cube 与 vector 相位交错、K/V 预取）

**两者相乘**：tiles 减半（1.38×）× 系数减半（推进到 83.5+1.46×9833/1000 = 97.9 ms → 1.58×）
→ 合计可超 1.5× 目标。

## 七、诚实边界

- 拟合基于 4 个点、单一形状（N=41792, B=1, H=7, D=128），**未在其他形状验证**。
- `83.53 ms` 截距的含义是"tile 数趋于 0 时的外推"，**不是可达到的下限**——
  真实下限受 cube 计算约束（R190 算的 1.44 µs/tile cube 下限）。
- 47% 这个比例是针对**当前基准配置**的，换配置会变。
- 改 tile 会改累加顺序 ⇒ **数值非等价**，仍只是测量，不能作为候选。
