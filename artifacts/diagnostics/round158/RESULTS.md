# R158 — 同步预取对照：**copy-stream 竞争假设被排除**

## 为什么做这个对照

R155：MLP 里 `fc1→fc2` 之间是可加的 **34.717 ms/层**，而 standalone 同一套算子 3.24 ms。
四个假设里前两个已排除（分配器 R156）。本轮检验第三个：**与异步 H2D 权重预取的竞争**。

做法：把 `LayerwiseOffloadHook.prefetch_layer` 强制成同步（`non_blocking=False`），
使 block 执行期间**没有任何拷贝在飞**。这是**纯诊断对照**，永不作为优化提案。

## 实测（8 rank 完成）

| 指标 | 异步预取（R155） | **同步预取（R158）** | 差 |
|---|---|---|---|
| step | 17.902 s | **19.597 s** | +1.695 s（拷贝不再重叠，如预期） |
| **激活区** | 34.717 ms | **34.76 ms** | **+0.043 ms（纹丝不动）** |
| `fc1` | 23.274 ms | 23.316 ms | +0.042 |
| `fc2` | 29.999 ms | 30.022 ms | +0.023 |
| 闭合误差 | 0.221 ms | 0.144 ms | — |

**结论：竞争假设 REJECTED。** 如果该区间在等权重流，去掉在飞拷贝后它应当塌掉；它没有。

## 至此四个假设全部排除

| 假设 | 证据 | 状态 |
|---|---|---|
| 分配器重试 / OOM 回退 | R156：`num_alloc_retries`=0、`num_ooms`=0 | **排除** |
| H2D copy-stream 竞争 | R158：同步预取后区间不变 | **排除** |
| 逐元素算子本身慢 | R154：同形状 standalone 仅 3.24 ms | **排除** |
| 未做算子融合 | R125：fused SiluAndMul 无收益 | **排除** |

## 剩下什么

该区间在模型内是真实执行的设备工作，约为同一算子序列 standalone 耗时的 **10×**，
而四个环境解释都不成立。剩下的差异只有：
1. **模型内 fc1 输出的内存布局**（GEMM 直接产出的 tensor 是否带 padding / 特殊 stride）；
2. **该上下文下实际选中的 kernel**。

要看清这两点只有 **kernel 级 profile**（msprof op summary）。

## 决策：主线转向 #5

这条线已花 **6 轮**追 1.7 s。按目标优先级，**#5（FA，7.6 s/步）才是关键路径**，
且它需要用户批准才能改内核。下一轮把主力转到 **只读 FA 分析**，好在批准后立刻开工。

## 限制

- 同步预取使整体步时变慢，这是预期的诊断代价，不用于任何性能结论；
- 本轮的区间数值仍可与 R155 直接比较，因为测量口径完全一致（同一探针、同一闭合检查）。
