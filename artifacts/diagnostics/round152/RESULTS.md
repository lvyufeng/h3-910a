# R152 — SiLU 测量：**INCONCLUSIVE**（方法被污染），但假设被部分否定

## 结论先说

本轮**没有拿到可用数字**，原因是我自己的探针有两个缺陷。诚实记录如下。

## 实测（step 18.001 s，8 rank 完成）

| 项 | 原始 | 去重后 |
|---|---|---|
| `silu` 调用 | 312 次 / sum 996.3 ms | 104 次 / sum 332.1 ms |
| `silu` median / min / max | 0.276 / 0.004 / **219.21** ms | — |
| `mlp` 调用 | 150 次 / sum 18037.5 ms | 50 次 / 中位 88.16 ms |

## 为什么无效（三个缺陷）

1. **hook 被重复登记 3 次**（与 R149 同一个 bug 家族）：`_install_layerwise_hook_group` 被调用 3 次，
   我的 pre/post 各注册 3 份。pre 覆盖、post 按登记顺序 pop，结果记录的是"内层 start → 外层 end"的跨度，
   **sum 被放大且不稳定**。
2. **sum 被离群值污染**：`silu` 的 max = **219.21 ms**（几乎肯定是首次调用/JIT），
   而 median 只有 0.276 ms。用 sum 判断占比会严重失真。
3. **形状混合**：`silu` 在 4 种形状上被调用（`[[3, 2688], [3, 5376], [2043, 7168], [10448, 7168]]`），
   其中 `[3, 2688]`/`[3, 5376]` 是 adaLN 的小调用；median 被这些小调用主导，
   **无法代表 MLP 的 `[10448, 7168]` 那 50 次**。

## 唯一可信的锚点

`mlp` median **88.16 ms** 与 R149 独立测得的 **88.178 ms** 一致 → 跨度本身是准的，
错的只是聚合方式。

## 假设的处置：部分否定

- **原来假设**：mlp 残差 1.729 s 主要是 SiLU 的超越函数吞吐。
- **现状**：无法判定（测量无效），但 `silu` 全站 median 仅 0.276 ms 说明它**不是**一个"每调用几十毫秒"的量级，
  与"SiLU 主导"的直觉相悖。**我先下调该假设的置信度**，不下结论。
- **新的、更强的怀疑**：`hidden.chunk(2, dim=-1)` 返回**非连续视图**，随后 `F.silu(gate) * up`
  在 FP32 [10448, 14336]（约 600 MB）缓冲上按 stride 跑两次逐元素 pass。**跨 stride 访问 + 独立 mul**
  更可能是那 ~1.4 s 的来源，而且**改成连续 narrow 是数值无关的**（逐元素公式与求值顺序不变）。

## 下一步（修正清单）

1. 探针只登记**一次** hook（在 `probe.install` 里加幂等保护）；
2. **按形状聚合**：记录 (shape → count, sum, median)，把 50 次 `[10448,7168]` 单独拎出来；
3. **只信 median，不用 sum**；丢弃首调离群值（或单独记 warmup）；
4. 然后做 chunk/mul 路径的直接对照（连续 narrow vs 原 stride），量化那 1.4 s。

## 影响

S6 情景里 mlp 残差 1.729 s 是第二大项，本轮**不能**确认它可以减半，
因此 **S6 的结论暂时维持在"未验证"**，10 s 所需的 FA 效率仍是约 69 TFLOPS/卡（未因本轮而改变）。
