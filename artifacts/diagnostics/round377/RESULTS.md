# R377 — 可测数值不变的审计加速 + 端到端 profile 归因：15.94 s/step

## 一、端到端归因（msprof `--task-time=l1`，稳态 forward 15.20 s 窗口）

| 类别 | 时间 | 占 wall | 次数 |
|---|---|---|---|
| FA 内核（V1 128/384） | 5.805 s | 38.2% | 50 |
| **Cast（其中审计占大头）** | **2.172 s** | **14.3%** | 2402 |
| MatMul + MatMulV2 | 2.609 s | 17.2% | 245 |
| allReduce | 1.256 s | 8.3% | 98 |
| alltoall | 0.978 s | 6.4% | 196 |
| Mul/Add/Equal/Transpose/Reduce* | ~1.1 s | 7.2% | 3000+ |

**关键发现**：Cast 里最大的单项是 `Cast55 = view(int16).to(int32) [10448,14336]`（1.63 s，100 次）——
这不是模型 dtype 转换，而是**每步 155 条 Half 安全检查**的 `equivalent_safety126.half_safety_counts(fast=True)` 实现。

## 二、审计加速（语义完全不变）

原实现（每检查）：`npu_format_cast(NZ) + contiguous + view(int16).to(int32) + &0x7fff + 2×sum` = **24.4 ms**（大张量）。
新实现（早退）：
1. 先做一次 `value.abs().max()`（**4.5 ms**）；
2. 若 peak 有限且 `< 65504` ⇒ 不可能有 NaN/±Inf/边界值 ⇒ 两个计数**必然精确为 0**，直接返回 `(0, 0)`；
3. 否则回落到原实现，得到**完全相同**的精确计数。

### 等价性验证（NPU，8/8 全部 bit-equal）

| 用例 | old | new |
|---|---|---|
| random | (0,0) | (0,0) |
| mixed NaN/±Inf/±65504 | (12621, 8414) | (12621, 8414) |
| all 65504 | (0, 262144) | (0, 262144) |
| 65503.9（fp16 舍入到 65504） | (0, 65536) | (0, 65536) |
| big clean (10448×14336) | (0,0) | (0,0) |
| big with NaN | (0,1) | (0,1) |

- 严格模式语义不变：计数为 0 时不抛异常，非 0 时仍抛 `Half matrix range failure` 且计数一致；
- 主机读取（strict 同步点）保留：原路径每次检查一次 D2H，新路径同样一次（`max` 的结果）。
- 实现：`artifacts/deploy/equivalent_safety_fast377.py`（本次新增），env 开关 `H3_FAST_AUDIT=1`。

## 四、为什么审计只省 0.17 s（而非预估 1.5 s）

155 次检查里只有少数是大张量；且每次检查都带一次 **strict 模式同步**，同步开销与张量大小无关，
所以设备算子侧的 5.4× 加速只体现为 0.17 s。进一步压缩需要动"每检查一次同步"的语义（契约不允许）。
