# R209 — #15 根因假设：**HCCL 集合通信归约顺序不确定**（附决定性测试）

## 一、为什么现在做这个

按 AGENTS.md「只做 ready 任务」重新审了看板，发现 **#4（P0，worker-local copy stream / 安全 prefetch）
被 #15（P0，原生重复非位同）阻塞**。

而 #4 正是目标里列的第 #4 号候选「权重流重叠」——**它在 DiT 路径（96.4%）上**。
**解开 #15 就能释放 #4**，这是当前唯一一条既在 DiT 主路径上、又不需要数值批准的路。

## 二、先否掉了我自己的第一个假设

#15 的工作清单第一项是"检查输入 tensor 是否被某处改写、模型非参数状态"。
grep 出 28 处 in-place 操作，最可疑的是 `denoise_loop.py`：

```python
timesteps.fill_(float(t_video))
...
timesteps.copy_(_cpu_timesteps.to(timesteps.device, dtype=timesteps.dtype))
```

**假设**：若 `timesteps` 是常驻 buffer 且异步拷贝无同步，会读到旧/半成品数据。

**读代码后否掉**：第 201 行是 `timesteps = torch.empty(...)` **每次新分配**；
`.to(device)` 也产生新张量。且注释明确写着
`910A: build the packed timestep vector on CPU and copy it back once` —— 是有意设计。

⇒ **这不是根因。**（记下这个否证，避免以后再查一遍。）

## 三、三五条独立证据指向同一个方向

| 测量 | 现象 | 来源 |
|---|---|---|
| DiT 50 块 native 重复 | video relRMS **0.0262%**，maxabs 0.0169 | R128 |
| **encoder native 重复** | **96.1–96.4% 输出词不同**，relRMS 0.88–2.32% | R137 |
| video VAE decode 重复 | 0.066% 分量不同，**1 LSB** | R138 |

**三个完全不同的组件都不可重复。** 共同因素只有两个：NPU 硬件/库、以及**集合通信**。

而 R137 有一个关键细节：**encoder 的隔离运行（8 次）全部互不相同**，且
`encoder.text.layers.0` 的 post 输出就已经在变（事件序号 62）——
**偏差在最浅层就出现**。

## 四、假设：**HCCL all-reduce 归约顺序不确定**

- encoder 走 **TP8**：每层 attention 的 row-parallel `all_reduce`、MLP 的 `all_reduce`
- DiT 走 **TP2 + USP4**：同样每层多次 all-reduce
- VAE 也做 tile gather（USP 集合通信）

**若 HCCL 的 all-reduce 使用非确定性归约顺序**（常见于 ring/tree 混合或原子累加实现），
则**同一输入每跑一次结果都不同**，且：
- 偏差随**层数累积** ⇒ encoder 64 层 → 96% 词不同（大）
- DiT 逐块，但每步都重新累积 ⇒ relRMS 0.026%（小但稳定可见）
- VAE 只有少量 gather ⇒ 1 LSB 级抖动

**这个模型能同时解释三个组件的现象，且量级关系合理。**

## 五、决定性测试（便宜、可判定）

**设 `HCCL_DETERMINISTIC=1`（CANN 的集合通信确定性开关）重跑同一输入重复。**

| 结果 | 结论 |
|---|---|
| 变化消失（逐位相同） | ✅ **确认是集合通信归约顺序**，根因定位 |
| 变化仍在但变小 | 部分贡献，需继续分离 |
| **完全不变** | ❌ 假设否掉，回到"算子级非确定性"方向 |

**成本**：只需在现有 R128/R137 的重复测法上加一个环境变量，不必改代码、不改数学。
**这是 #15 里最便宜的一个决定性实验。**

### 配套的分离测试（同轮可做）

1. **单卡（不启用集合通信）**跑同一输入重复 —— 若单卡可重复，则必然是集合通信；
2. **TP2 vs TP8** 对比 —— 若偏差随 TP 度增大，进一步支持；
3. 用 #15 工作清单里的"无额外 sync 的重复控制"，避免 sync 掩盖 race。
