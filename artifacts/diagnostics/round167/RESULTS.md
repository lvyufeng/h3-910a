# R167 — 位模式检查：**465 次真实调用严格计数等价**；收益修正为约 0.6–0.7 s

## 正确性（双重证明）

| 验证 | 结果 |
|---|---|
| R166：37 个用例（16 构造边界 + 21 随机模糊，含 [10448,14336] 等真实形状） | 判定 0 不一致、计数 0 不一致 |
| **R167：465 次真实被审调用** | **计数 0 不一致**（`exactly_count_equivalent = True`） |

位模式实现与原实现在**两个计数（非有限、饱和）上完全相等，含多重性**。

## 代价：中位更慢、总量更省

| 项 | 原生 | 位模式 |
|---|---|---|
| 中位/次 | **24.568 ms** | 30.522 ms（更慢） |
| **每步设备总耗时** | 6.656 s | **4.808 s** |

**中位悖论**：位模式中位更差、总量更低 → **原生分布有很重的长尾**（format cast + int32 扩张 + 3 个 mask 在部分调用上极慢）。决定步时的是总量。

## 收益预期修正（重要）

R162 关掉审计：步时降 2.87 s，而原生检查约 8.3 s 设备时间 → **折算比约 0.35**。
套到本轮 **1.848 s 设备节省** → **净步时约 0.6–0.7 s**，不是我 R163 后说的 1.5–2 s。**修正那个偏高的预期。**

## 剩余成本仍大

即便换位模式，检查仍要 **4.808 s/步**设备时间。进一步压缩需**把 int16 视图上的工作融合成单趟 kernel**。

## 边界

本轮为验证：原生判定为权威、检查未删、未采纳。采纳不改模型算术，且计数等价已被两轮独立验证。
