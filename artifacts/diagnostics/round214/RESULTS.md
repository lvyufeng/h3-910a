# R214 — 补测 all-to-all / reduce-scatter / all-gather：**四个原语全部可重复**（含我自己的假阳性）

## 一、为什么补这个

R210 我只测了 **all-reduce**，这是明确的漏洞：**USP（`--usp 4`）重度依赖 all-to-all**，
而 reduce-scatter / all-gather 也从未测过。R213 把这个列为第一优先候选。

## 二、第一次运行：出现"不可重复"的 all_gather

首跑结果：

| 原语 | distinct | 可重复 |
|---|---|---|
| all_reduce_sum | 1 | ✅ |
| all_to_all_single | 1 | ✅ |
| reduce_scatter | 1 | ✅ |
| **all_gather** | **10** | ❌ |

**看起来找到了根因。但我先检查了自己的代码，发现：**

```python
for _ in range(REPEATS):
    inp = torch.randn(chunk, ...)      # ← 每次循环都新建随机输入！
```

**是我的 bug。** 其他三个测试都 `clone()` 同一个 `base`，只有这一段在循环内 `randn`，
**每次输入都不同，当然输出不同。**

**⇒ 这是假阳性，不是 HCCL 的问题。** 在报告前抓住了。

## 七、下一步建议（成本递增）

1. **两卡最小复现**：只跑 TP2、单 block、同输入重复 —— 若两卡就可复现非位同，
   则不必碰 50 块就能定位；成本约几分钟。
2. **单 block 单卡 vs 单 block 多卡**：分离"多卡"这个变量。
3. **多流对照**：把 copy stream 与 compute stream 合并（单流）后重复。

**第 1 项最划算** —— 它把问题从"50 块 × 8 卡"缩到"1 块 × 2 卡"。
