# R201 — 我自己的流程错误：在**用户已暂停**的路径上做了三轮工作

## 一、错误

R198–R200 我转向 video VAE，理由写的是"encoder、video VAE、A2/A3 是不受 DiT 决策阻塞的并行目标"。

**这个判断错了。** `PERFORMANCE_STATUS.md` §4 第 5 条明明写着：

> 5. **video VAE 剩余 1.7 s**：**用户已暂停该路**。

我**没有读自己文档里的"已暂停/已阻塞"清单**就下结论说它"unblocked"。
而且我在 R200 还写了"本轮开始执行这个顺序（先确认量受什么约束，再算）"——
结果连最基本的"这条路用户让不让做"都没确认。

**这是我这轮最需要记下的事。** 三轮的 VAE 分析本身没有错（模型验证通过了，
`clip_length` 不可调的结论也是真的），但**它不该被当成当前工作**。

## 二、反而发现了一个真正的文档缺陷（这个更有价值）

§6「十八条不要再走的结论」第 3 条这样写：

> - **写单趟统计内核**（阶段 A）：**唯一可行路线**，实测标定价值 **2.52 s/步**（R178），
>   但 **op 化构建尚未打通**（见 §3b）。

**这句话已经过时，而且过时的方向对用户不利：**
它读起来像"阶段 A 还没做出来"，实际上 **R182–R186 已经把它完整做出来并验证了**：

| 项 | 状态 |
|---|---|
| op 化构建（ascend910 + bisheng wrapper） | ✅ 打通（R182/R183） |
| 判定等价（对抗用例） | ✅ 15/15（R183） |
| 判定等价（真实张量） | ✅ 310/310（R186） |
| **端到端实测** | ✅ **17.987 → 15.473 s，省 2.514 s**（R185） |
| 默认路径 | 未改（`H3_FAST_AUDIT` 默认关） |
| **当前状态** | **Awaiting approval（等你批准）** |

**"尚未打通" vs "已打通并在等你批准"是完全不同的两件事。** 写成前者会让你以为
这项工作还没有产出，从而不去做那个只需要一句话的决定。
