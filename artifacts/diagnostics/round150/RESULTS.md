# R150 — FA/USP 事件级精测：更正上轮一个数字，并确认 10 s 不可达

用 R126 已验证的注意力 profiler（逐次断言无同步），**baseline 模式**跑（避免 harness 的同步区域 hook），
step **18.027 s**，8 rank 全部完成。

## 实测（每步 50 次调用）

| 区域 | 合计 | 每次 |
|---|---|---|
| **FA.ACL_launch（真实 kernel）** | **7606.7 ms** | 152.1 ms |
| FA.padding | 83.6 ms | 1.7 ms |
| FA.core | 7645.7 ms | 152.9 ms |
| FA.wrapper（含 Python 边界） | 7736.2 ms | 154.7 ms |
| USP pre / post | 809.4 / 277.8 ms（合计 1087.1） | 16.2 / 5.6 ms |
| q / k norm | 230.5 ms | 2.3 ms |
| attention 内部残差 | 1355.9 ms | — |

## 更正上一轮的推测

R149 的 FA 是 Python 级 wrapper 口径（8.199 s），我当时推测"约 0.75 s 是包装开销、可能有免费空间"。
**精测结果：FA wrapper 只比 kernel 多 129.5 ms**（0.130 s），不是 0.75 s。
**这条路没有可回收空间**，我撤回那个推测。

## 10 s 的算术（比上轮更硬）

| 项 | 值 |
|---|---|
| 现状 | 18.027 s |
| 需削减 | **8.027 s** |
| FA kernel 本身 | **7.607 s**（占 42.2%） |
| **FA kernel 归零后仍剩** | **10.42 s** |

**要 10 s，必须把 attention kernel 开销几乎全部消掉（今天 7.607 s），然后还要再找出 0.42 s。
任何"2× 级别"的 kernel 改进都到不了。**

## 数值无关的可回收空间（已量化）

| 项 | 时间 |
|---|---|
| attention 内部残差（rope/转置/dispatch 等） | 1355.9 ms |
| FA wrapper 开销 | 129.5 ms |
| 合计 | **约 1.49 s** |

即使全拿到，也只能到约 16.5 s；叠加 GEMM 达独立速率（−2.26 s）与 guard（−1.68 s，身份未证）约 12.5 s。
**与 R149 的"现实下限约 12 s"一致。**

## 结论

**10 s/step 在当前合同（TP2+USP4、原 50 块/49 步、FP16+FP32 保护、155 checks、禁用 sparse/近似/少步/降精度）下不可达。**
需要你在三选一里给方向：修订目标 ≈12 s / 授权改数学合同 / 授权改硬件与并行方案。

## 限制

- USP 与 q/k norm 是本轮实测（R126 值 1.077/0.230 s 与之一致）。
- attention 残差是父区间减去已知子区间的差，未逐算子拆解。
- 本轮未改数学、未安装候选、未采用任何 tolerance。
