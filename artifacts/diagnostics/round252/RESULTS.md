# R252 — guard 快路径：逐位一致、**−0.201 s**；并发现 guard 的 fallback 真的会触发

## 一、候选设计（基于 R251 的 msprof 证据）

R251 窗口里 `Cast`（stream 40，每块 2 次、每次 5–20 ms）指向两个受保护层（`out_proj`/`fc2`）
的 FP32 guard。部署路径为：

```
product = x.float();  peak = float(product.abs().amax());  scale = 2**ceil(log2(peak/32752)) or 1
half = (product / scale).to(fp16);  result = mm(half, w.t(), out_dtype=fp32) * scale
```

**当 scale==1 时**：`product/1.0` 是 x 的精确 FP32 像，`.to(fp16)` 逐位还原 x，`result*1.0` 精确
⇒ 直接把 FP16 的 x 送进同一个 mm 与部署路径**逐位相同**（R221 曾在 112,336,896 个真实 word 上验证）。

快路径保留 guard 语义：仍算 peak、仍做 host 同步、非有限仍抛错；**peak > 32752 时原样回落到部署实现**。
仅进程内替换 `apply`，不改盘上源码。

## 二、结果

| 项 | 值 |
|---|---|
| 合成逐位门（393,216 words，含 near-limit 用例） | **逐位一致，0 个差异** |
| 步时（8 rank 一致） | **17.7266 s** |
| 基线 | 17.928 s |
| **节省** | **−0.201 s（1.1%）** |
| 调用统计（rank 0，2 步） | fast **204**、fallback **6**、nonfinite 0 |
| 数值 vs R124 | video relRMS **8.92e-04**（基线带 9.84e-04–1.077e-03 ⇒ **带内**） |

## 三、两个重要结论

1. **数值上完全安全**：合成门逐位一致；实模型 relRMS 8.92e-04 落在基线自重复带内，
   且**比基线还低**。这是第一个“可证明不改数值”的性能候选。
2. **guard 不是死代码**：`fallback_calls = 6`（rank 0/1，2 步内），说明**真实激活确实会超过 32752**，
   scale>1 分支是活的。这修正了“scale 恒为 1”的直觉，也证明快路径的回落设计是必要的。

## 四、但收益远小于预期

R251 推断 Cast 值 1.5 s/步，实测只省 **0.201 s**。说明那 1.5 s 的 `Cast` 主要不是 guard 的
FP32 临时量（可能包含 encoder/其它路径的转换，或与计算重叠而未真正暴露）。
